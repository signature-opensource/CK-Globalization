# Translation

This folder contains the translation side of [CK.Globalization](../README.md): the
[`PositionalCompositeFormat`](PositionalCompositeFormat.cs) that is a parsed translation format and the
[`TranslationService`](TranslationService.cs) that applies them. The cultures and their fallbacks are
described in [ExtendedCultureInfo](../ExtendedCultureInfo/README.md).

## NormalizedCultureInfo cached translations
All `NormalizedCultureInfo` (except the "en" and Invariant default ones) can have a cached translation set of resources.
It can always be set (the new one replaces the current one). This is a thread safe atomic operation:

```csharp
public IReadOnlyList<GlobalizationAgent.Issue> SetCachedTranslations( IEnumerable<(string ResName, string Format)> map )
```
An overload accepts an `IEnumerable<KeyValuePair<string, string>>`. Calling it on a default culture ("en" or Invariant)
throws an `InvalidOperationException`.

The `Format` string is a positional-only composite format (see https://learn.microsoft.com/en-us/dotnet/standard/base-types/composite-formatting):
only `{0}`, `{1}` etc. placeholders are allowed, without alignment nor format specifier. This format string is parsed and kept as a
`PositionalCompositeFormat`, a structure optimized to generate strings. If the format cannot be parsed successfully, a
`GlobalizationAgent.TranslationFormatError` is returned. When the same resource name appears more than once, the first one is
kept and a `GlobalizationAgent.TranslationDuplicateResource` is returned. These issues are also raised by the
`GlobalizationAgent.OnNewIssue` event when the `GlobalizationAgent.Track` static gate is opened.

As discussed in [ExtendedCultureInfo](../ExtendedCultureInfo/README.md#extendedcultureinfo-and-normalizedcultureinfo), translations
must be "compact": a resource defined in "es-es" MUST be defined in "es" but because translations can be
set in any order (specific "es-es" before more generic "es") and setting the set is a lock-free operation, we don't check this
requirement. If a neutral (top culture like "es") misses a resource, the resulting `MCString` has a `Bad` or `Awful`
translation quality and a `GlobalizationAgent.MissingTranslationResource` is emitted (when `GlobalizationAgent.Track` is opened).

Calling `SetCachedTranslations` by hand is one way in. Two others exist and are worth knowing about:
- [`GlobalizationFileHelper.SetLocaleTranslationFiles`](../GlobalizationFileHelper.cs) loads a folder of `.json`/`.jsonc`
  translation files at runtime (one folder per culture, a specific culture folder lies in its neutral culture folder).
- [`GlobalizationTranslationInstaller`](../GlobalizationTranslationInstaller.cs) is a real object carrier whose
  `ApplyTranslations` body is generated by the CK.Globalization.Engine aspect from the merged per-package `Res/locales`
  translations, so an application can start with its translations already registered and no file to read.
  For this engine (a package that depends on this one), see
  [CK.Globalization.Engine](https://github.com/signature-opensource/CK-Globalization-Engine/blob/stable/CK.Globalization.Engine/README.md).

## TranslationService and MCString
The translation is primarily synchronous and relies on the basic cached translations carried by
the `NormalizedCultureInfo`. It can be specialized with more advanced caching capabilities and may
support asynchronous translation.

```csharp
public class TranslationService : ISingletonAutoService
{
    public virtual MCString Translate( CodeString s );

    public virtual bool SupportAsyncTranslation => false;

    protected static MCString? TryTranslateGood( CodeString s );

    public virtual ValueTask<MCString> TranslateAsync( CodeString s );
}
```
`Translate` looks up the `CodeString.TargetCulture` primary culture and then its fallbacks: the first culture that has a
translation for the `CodeString.ResName` wins. When the "en" code default is reached (or nothing is found), the string is
not translated. The default `TranslateAsync` simply calls `Translate`: it may be overridden if translations can be obtained
from external repositories (`SupportAsyncTranslation` should then be true). `TryTranslateGood` is a helper for such
specializations that only considers the cultures with the same neutral culture as the primary one.

The translated [`MCString`](../MCString.cs) wraps its source `CodeString` and exposes the `FormatCulture`, the translated `Text`
and a `TranslationQuality` (`Awful`, `Bad`, `Good` or `Perfect`).

## The ResName is optional but important
When a developer is in a hurry, he may not have time to choose and set a resource name for a CodeString.
In this case, an automatic resource name is computed: "SHA.v8xu6U8beqBaBHUJA-Jfk6cYiuA" for instance
is the default resource name of the plain text "text" (it is the base64url encoding of the SHA1 of the
text where the placeholders' contents are replaced by a mark: see `FormattedString.GetSHA1BasedResName()`).

This resource name can perfectly be used in the translation resources: the developer is not required
to choose a resource name. Translations can come later and provided without necessarily updating the
source code... or never if English is fine.

SHA1 automatic resource names never clash by design. When multiple locations in source code create
the same CodeString, their SHA1 are equal and the same resource will apply to all of them. If a developer
changes one of them, it will become "untranslated" until a dedicated resource is provided.

Explicit resource names seems better, but the same name can be defined by 2 different developers (in 2
modules) with a totally different format string.

SHA1 or explicit, managing resource names requires to take care of:
- A change in the number of placeholders (the user will see messages with "holes" in them).
- The removal of a CodeString (the resource will be defined for ever, polluting the system).

These issues are tracked dynamically by the `GlobalizationAgent` (see [the globalization issues](../README.md#the-globalizationagent-and-the-globalization-issues)).
